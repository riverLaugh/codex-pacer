# 本机后台任务监控 · PRD v1

## 用户与目标

用户让 agent 启动一个批处理后，会切换到其他会话或关闭聊天。他想知道程序处理了多少项、几项失败、结果是否已经确定，并在需要时回到发起任务的聊天。

第一版在 Mac 和 Windows 的展开任务面板显示本机后台程序的计数。代理负责登记，执行程序负责提供事实，Pacer 负责读取和展示。普通会话继续使用现有的百分比上报。

## 使用流程

1. 用户在本机 agent 中启用 Pacer 的任务登记 MCP。Agent 为本次运行生成一个 UUID，准备好状态文件的绝对路径，调用 `track_task(run_id, title, status_file)`。登记可以早于文件的第一次写入。
2. 程序在项目目录内原子替换一个 UTF-8 JSON 文件。一个文件对应一次运行。启动第二批时使用新的 UUID。第一版使用有明确总数的计数任务。
3. 展开灵动岛，可以看到独立任务行。已有可信的 Codex 会话标识时，用户可以从任务行返回发起会话。会话关闭、agent 退出、Pacer 重启后，登记继续有效。
4. 显式结束后保留最终计数供查看。用户可按运行 ID 取消跟踪。此操作只移除 Pacer 自己的登记和缓存，执行程序仍由用户控制。

## 状态文件约定

```json
{"run_id":"16551ce1-f8aa-427f-8d97-a6e84bea9499","state":"running","succeeded":340,"failed":2,"total":1000}
```

处理量为 `succeeded + failed`，上例显示「已处理 342/1000 · 失败 2」。全部计数为非负整数，已处理量最多等于总数。零项任务可显式完成。状态值为 `running`、`completed`、`failed`。

完成要求程序显式写入 `completed` 且已处理量等于总数。单项失败仍计入已处理量。程序整体提前终止可写 `failed` 并保留实际计数。读到终态后，该运行的结果固定。等待第一次写入时显示「等待首次更新」。缺失、损坏、运行 ID 不符或计数不合法时，保留最后一次有效读数和更新时间。静默时间只说明数据的新鲜度。

## 验收场景

| 编号 | 操作 | 可观察结果 |
| --- | --- | --- |
| A1 | 同一会话登记两次不同运行，重试其中一次 | 看见两个独立任务。同一 ID 登记到另一文件时收到冲突提示 |
| A2 | 写入示例数据，结束发起会话，再写入新计数 | 从 342 项更新到新计数，任务保持运行；运行中即使到达总数也等待显式结束 |
| A3 | 重启 Pacer；临时移走文件、写入截断内容或放入另一批任务的数据 | 保留该运行上一次有效读数；文件恢复后继续更新 |
| A4 | 分别写入全部成功、部分项目失败、整体提前失败和空任务结果 | 显示对应的终态与计数；后续迟到的运行中数据不能把任务重新打开 |
| A5 | 取消跟踪，再次取消并重启 | 任务消失，重复操作安全，原始状态文件仍可用 |
| A6 | 开启“隐藏项目名称”；登记时有或没有可信的来源会话 | 隐藏任务标题；有来源时可跳回，无来源时仍可跟踪 |
| A7 | 将 MCP 和后台作业作为独立进程，期间关闭再启动读取端 | 从真实文件恢复运行，最终读到与作业一致的成功数和失败数 |

## 范围与验证

本版支持本机显式登记、单写入程序、双语展示和进程重启恢复。SSH、WSL、任意命令探针和主观步骤清单留给后续版本。文件只包含计数和运行状态。Pacer 本机保存登记所需的短标题、路径、可用的来源会话标识和最后一次有效读数。展示层继承“隐藏项目名称”。

开发按需求、失败用例、最小实现、回归测试推进。协议、跨进程恢复和异常输入可自动测试；双端界面另做原生构建与实际交互检查，每项分别记录结果。


## Mac 任务行的会话关联与清除

有来源的任务显示可点击的会话名称。名称暂不可用时，显示可识别的会话编号。未关联的任务提供“关联会话”，供用户从本机最近的 Codex 会话中选择，重启后保留选择。隐藏项目名称时也隐藏会话名称。

已完成或明确失败的任务提供“清除”。该按钮移除所选运行及其 Pacer 缓存，保留作业文件、Codex 会话和其他运行。等待或运行中的任务没有清除按钮。已有登记无需迁移。
